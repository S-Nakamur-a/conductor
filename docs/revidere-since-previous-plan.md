# 実装計画書: 前回のレビューからの進みを出す

- 日付: 2026-08-13
- 起点: PR #319「revidere をベースから作業ツリーまでの全差分でレビューする」から
  切り出した追加分。#319 はレビュー範囲の修正で、こちらは表示の追加。混ぜると
  「画面が変わった」のがどちらの由来か切り分けられなくなるので分けた。
- ステータス: 実装・実機確認済み。

## 現状

レビューは毎回ゼロベースで作り直す (#319)。これは正しいが、2 度目以降の読者は
「前に読んだときから何が動いたのか」を知る手立てが無く、全部を読み直すことになる。

前回の対象コミットは成果物にしか残っていない。#319 で `head` が解析時の HEAD
コミット ID になったので、初めてここを起点に差分を語れるようになった。

## ゴール

レビュー本体はゼロベースのまま、「前回のレビューから何が動いたか」だけを別に
持たせる。最低限、前回と今回のコミット ID、その間で変わったファイル、履歴が
書き換わったかどうか。

## 非ゴール

- 前回の分類 (節・重要度) の持ち越し。履歴が書き換わったときに、何が根拠だった
  のか誰にも分からなくなる。
- ~~前回からの差分だけをレビューするモード。~~ ファイル名の一覧では
  「指摘をどう直したのか」が読めないと分かったので、下の「追加」で入れた。
  ただしモードではなく、同じ画面の中で見る区間を切り替える形にしてある。

## 実装

| 置き場所 | 中身 |
|---|---|
| `crates/revidere/src/review.rs` | `SincePrevious` (previous_head / head / files / history_rewritten) と `Review` の任意フィールド |
| `crates/revidere/src/analyze.rs` | `previous_head()` が上書き前の成果物を読み、`since_previous()` が git から引き直す |
| `crates/revidere/src/git.rs` | `is_ancestor_of_head` と `changed_files` |
| `crates/revidere/src/annotate.rs` | 読み側のアクセサ |
| `src/ui/revidere_view.rs` | `push_since_previous` — 概要の先頭に出す |

版は conductor 0.107.0 / revidere 0.5.0
(`artifact_path` の引数と `Options` のフィールドが増えるので破壊的)。
成果物のスキーマは上げていない
(`serde(default)` の任意フィールドなので、古い成果物もそのまま読める)。

### 決めたこと

- **成果物は上書きする前に読む。** 前回の対象コミットはそこにしか残っていない。
- **HEAD が動いていなければ起点も動かさない。** 解析し直すだけで起点が今になると、
  読む前に最新化した人から進みが消える。差分が動いていなければ AI を呼ばずに即座に
  返る操作なので、ただの空振りに見えて実際には成果物を上書きしていて、前の起点は
  もうどこにも残っていない。
- **スキーマ版が違う成果物は読まない。** `head` の意味は版によって変わりうるので、
  読めた文字列をコミット ID として扱うのは推測になる。
- **ファイル一覧を引けなかったことを「無い」に畳まない。** 前回のコミットがもう
  残っていなければ `git diff` は失敗する。それを空の一覧にすると、山ほど動いていても
  「変わったファイルは無い」と言い切ることになる。`files` は `Option` で持つ。
- **一覧は git を先に引く。** AI の応答を待つ数分の間に HEAD が動くと、成果物に
  書く `head` と一覧が別々の時点を指す。
- **`files` は前回の HEAD から「今の作業ツリー」まで。** コミット間ではなく、
  レビューが実際に見ている範囲に合わせた。未追跡ファイルも繋ぐ — 新しく足した
  ファイルが「変わっていない」側に落ちると、一番読みたいものが消える。
- **履歴が書き換わっても止めない。** rebase 直後はオブジェクトが残っていることが
  多く、ファイル一覧は取れる。取れなければ一覧を諦めて、履歴が変わったことだけを
  伝える。画面ではその旨を警告色で断る。

## 分かっている穴

- **未コミットのまま解析し直すと、前回も読んでいた変更が「進み」に混ざる。** 起点は
  前回の解析時の HEAD なので、コミット済みの分は正確に引ける。ただし前回の成果物も
  作業ツリーまで見ていて、その未コミット変更はコミット ID では名指せない。
  厳密にやるなら解析のたびに作業ツリーを tree object として書き出して持つことになり、
  レポジトリに gc されないオブジェクトが育つ。そこまでの対価は払っていない。
- **未追跡ファイルは起点と関係なく毎回載る。** どのコミットにも属さない以上「前回の
  HEAD より後に生えたか」は git に訊けない。多めに出る方向の誤りなので、読み飛ばしは
  起きない。
- **一覧に追加・削除・rename の区別が無い。** `--name-only` なので rename は新しい名前
  だけが出て、消えた側は現れない。
- 前回の HEAD が完全に消えている (gc 済み) と `files` は `None` になり、一覧の代わりに
  引けなかった旨が出る。

## 追加: 前回からの差分を「レビューとして」読む

ファイル名の一覧までしか出ないと、肝心の「指摘をどう直したのか」が読めない。
指摘そのものは conductor の外 (Claude Code の会話や GitHub) にあって取り込めない
以上、直しを確かめる手立ては差分を読むことしかない。

画面は増やさず、レビュー画面に「見る区間」の軸を 1 本足した。`o`/`d` が列の軸、
`p` が区間の軸。ブランチ全体と「前回のレビューから」を行き来する。自然言語の説明も
コード diff も、同じ切り替えで一緒に入れ替わる。

| キー | 軸 | 効果 |
|---|---|---|
| `o` / `d` | 列 | 概要 1 列 / 項目 + diff 2 列 |
| `p` | 区間 | ブランチ全体 ⇄ 前回のレビューから |
| `W` / `alt+w` | — | いま見ている区間を解析 (画面内からも押せる) |

- **成果物は区間ごとに別ファイル。** `review.json` と `review-since-previous.json`。
  1 枚に混ぜない — 網羅性 (全ての変更箇所がちょうど 1 つの項目に属する) は区間ごとの
  性質で、混ぜると検査が意味を失う。
- **前の回の差分レビューは「まだ解析していない」に寄せる。** 起点が今の前回と違えば
  見ている区間が違う。壊れてはいないので `Broken` ではなく `Missing`。直しを読んで
  いるつもりで 1 つ前のラウンドを読む事故を防ぐ。
- **前回からの差分のレビューは `since_previous` を持たない。** それ自体が進みなので
  入れ子になる。
- 区間はホスト側の状態。ライブラリには `Scope` と、区間を受け取る `artifact_path`
  だけを足した。

## 実機で確かめたこと

自動テストが見ていない画面側を、成果物を差し替えながら実際の TUI で読んだ。

- 成果物に `since_previous` が無いとき、概要に節ごと出ない
- 前回と今回のコミット ID、変わったファイルが概要の先頭 (5 欄より前) に出る
- 履歴が書き換わった旨の断りが警告色で出る。文面は 2 行以上に折り返り、幅 60 桁まで
  狭めても枠内に収まる
- 一覧が引けないとき、「無い」ではなく引けなかった旨が出る
- 一覧が上限を超えると先頭だけ出て、残りは件数に畳まれる

区間の切り替えも実機で確かめた。実際に `b8aea97..作業ツリー` を解析させ (17 ファイル /
444 変更箇所 / 19 項目 / 説明もれなし)、TUI で読んだ。

- `w` で開いた直後は `[ブランチ全体] 1df38a4..作業ツリー`
- `p` で `[前回のレビューから] b8aea97..作業ツリー` に替わり、概要も diff も入れ替わる
- `d` の 2 列表示でも見出しに区間が出て、右列は前回からの差分だけを歩く
- もう一度 `p` でブランチ全体に戻る
- 起点の違う (前の回の) 差分レビューしか無いときは、それを出さずに
  「まだ解析していない」として扱い、次にどうすればよいかを出す
