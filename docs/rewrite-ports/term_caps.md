# term_caps
旧テスト 6 本 → 新テスト 4 本

| 旧テスト名 | 扱い | 新テスト名 / 削除理由 |
|---|---|---|
| 設定済みなら自動テーマはnoneを返す | 移植 (統合) | 自動テーマ選択は設定済みか暗い背景ならnone明るいときだけlatte — table-driven に統合 |
| 明るい背景ではlatteを選ぶ | 移植 (統合) | 同上に統合。同じ関数 `auto_theme_for_background` を境界値違いで並べているだけで、テーブルの1行にしてもどの入力→出力の対応も落ちない |
| 暗い背景ではnoneを返す | 移植 (統合) | 同上に統合 |
| osc11の応答はどの綴りでも輝度を読める | 移植 | 同名で移植 (元から table-driven) |
| シンボルを同梱する端末だけnerdと判定する | 移植 | 同名で移植 |
| 判らない端末では推測しない | 移植 | 同名で移植 |

3本の `auto_theme_for_background` テストは同じ関数の異なる入力に対する期待値を
1本ずつ別関数で書いていただけなので、`(輝度, 設定済みテーマ, 期待値)` のテーブル1本に
まとめた。境界値 (0.5 ちょうど、設定済み+暗い背景の組み合わせ) を含め、旧テストが
固定していた入出力の対応はすべてテーブルの行として残っている。

API 変更: `read_osc11_response()` を新規に private 関数として抽出し (旧コードは
`query_background_luminance()` 内にポーリング・読み取りループがインライン展開されていた)、
公開 API 自体は変更なし。`OSC11_TIMEOUT_MS` を関数ローカル定数からモジュール定数に格上げ。

残したコメント (なぜ): raw mode 突入後・crossterm のイベントループ開始前に問い合わせる
必要があるという I/O 順序の制約 (実測した外部の癖)。OSC 11 応答を1バイトずつ読む理由
(後続のグラフィックスプロトコル応答へバイトを漏らさないため)。tmux passthrough の制限。
