## API 変更

1. **`build_index` が印字しなくなった。** 旧は `println!` / `eprintln!` で結果を出し
   `Result<()>` を返していた。新は `Result<BuildOutcome>` で、`BuildOutcome { built: Vec<Built>,
   failures: Vec<String> }` を返す (`Built { index, documents, missing_provenance }`)。
   1 本も作れなかったときだけ `Err` になる挙動は同じ。core が stdout を持たないための変更で、
   印字は `conductor index` の呼び出し側の責務。**呼び出し側 (旧 `src/startup.rs:42`) の対応が要る。**
2. **`semantic_index::same_language` を持ち込まなかった。** `symbol_index::same_language` に
   移っており、唯一の利用側だった `symbol_index/index.rs` も移植済みでそちらを使っている。
3. `roots::Language::of_file` は目印ファイルの判定だけを持ち、拡張子は
   `symbol_index::Language::of_path` に委譲する (`for_marker(name).or_else(|| of_path(path))`)。
   `.jsx` / `.mjs` などの綴りが 2 箇所に散らない。
4. `owning_root_of(&[IndexRoot], rel)` → `roots::owning_index(impl Iterator<Item=&IndexRoot>, rel)`。
   旧は毎フレームの `note_open` / `note_change` から呼ぶたびに全ルートを `clone()` して
   `Vec` を作っていた。反復子で受けるとその複製が消える。
5. `IndexRoot::content_key(tree_root, deeper: &[PathBuf])` →
   `content_key(tree_root, all: &[IndexRoot])`。`deeper_than` の呼び出しが 3 箇所
   (survey / build_index / テスト) に散っていたのを中に入れた。
6. `IndexRoot::fold` は `pub(super)`、`roots` モジュールは `pub(crate)`。`IndexRoot` は
   `semantic_index::IndexRoot` として再輸出するので、旧の利用側の書き方は変わらない。
7. `#[cfg(test)] SemanticIndex::with_root` を足した。旧テストは構造体リテラルで
   `SemanticIndex` を組み立てていたが、フィールドを非公開のままにするため入口を 1 つ切った。

## 実リポジトリ依存の外し方

`#[ignore]` の実索引テストは、旧は `src/hover_info.rs` / `src/jump_history.rs` /
`src/background.rs` などのファイル名を直に書いていた。書き直しでこれらは消えるので、
索引が実際に説明できている `.rs` を `store.is_current` で選ぶ `covered_rust_files` に
置き換えた。測っている事実 (答える割合、宣言と種別が読める割合、飛び先が実在する、
1 クエリ 100ms 以内、種別が 5 種類以上) と閾値は変えていない。旧の `own()` が
クレート名の直書きで「自前のシンボル」を絞っていたところは、「ツリーの中に定義がある
(= `Definition::Exact` が返る)」に置き換えた。同じ集合を指し、リポジトリに依存しない。

## 残したコメント (なぜ)

- 実測値: 索引ルート 109 本 / 列挙 149ms / 鍵 1 本 110ms / 全部の鍵 0.6 秒 /
  producer 1 本 14 秒・2.3GiB / 索引 1 本 14.5MB。「UI スレッドでやらない」「必要な
  ルートだけ鍵を出す」「ロックはリポジトリ単位」「世代は 4 本」の理由。
- `note_open` を毎フレーム呼ぶ理由 (開く経路が 12 箇所ある)。
- 鍵の無いルートで生成を始めない理由 (置く名前と中身が食い違う)。
- ツリーの照合を「前回と同じファイル」の早期リターンより前に置く理由 (worktree を移った
  あとに前のツリーの答えが残る)。
- 読み込み待ちの周で答えを確定させない理由 (古いと言うべき唯一の場面で必ず黙る)。
- 出自がファイル単位なので鍵のずれだけでは producer を起こさない理由。
- `stem()` が `_` を重ねる理由 (`a/b` と `a_b` の衝突)。
- `generations()` が鍵の形を検査する理由 (`index.go` と `index.go.api` の入れ子)。
- `changed_during` をファイルで持つ理由 (監視が 1 保存で複数イベントを上げる)。
- `history` が `key=value` で桁を揃えない理由 (grep の当て先が動く)。
- macOS の `/var` が `/private/var` への symlink で git2 は解決した側を返す (テスト)。
- 認識できないツリーに producer を向けると終了コード 0 で空の索引を書く (テスト)。
