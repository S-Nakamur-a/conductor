## API で変えた点

- 旧 `SearchResultTree` (行のキャッシュ + 画面の並びから親のパスを逆算する
  `resolve_dir_path`) → `SearchTree` は畳む前の行を 1 度だけ組み立て、行そのものが
  自分のキーを持つ。`NestedDir` / `DirNode` / `cached_rows` は消えた
- 旧 `GrepSearchOverlay` の `bg_op` / `bg_op_phase2` / `running` / `pending_matches` →
  `Task::Grep` の通し番号 1 つ
- 旧 `App::switch_repo` / `open_repo_from_path` → `Effect::SwitchRepo(PathBuf)`。
  受けた側 (`effect::switch_repo`) が世代を進めてからパネルを組み直す
- `conductor-svc`: `EventSender` が世代を写し取らず `Services` と共有するようにした。
  写し取ったままだと、リポジトリ切替で世代が進んだ瞬間に watcher の合図が永久に捨てられる
- 設定への書き戻し (テーマ / 高コントラスト / パネル比率) は `Task::PersistConfig`。
  UI スレッドでディスクに触らない

## 旧との挙動差

- grep の 2 段階検索 (3 文字以下のクエリで、まず最近変更されたファイルだけを検索し、
  並行して走るフル検索で置き換える) は入れていない。svc の 1 本の Task と通し番号に
  なり、`GrepProgress` の逐次配信も無くなったので、短いクエリでの初動は遅い
- resume と history の一覧はディスクと SQLite を読むので svc へ回した。旧は
  オーバーレイを開くその場で同期に読んでいた
- history の一覧と本文は上下 2 段。旧は左 30% / 右 70% の 2 列で、保存した出力が
  折り返しで潰れていた
- Help に j/k のスクロールを足した。Explorer のページは層が 3 つあり、旧の 30 行固定の
  ポップアップでは Global の節に届かなかった
- リポジトリを切り替えても cc-notify のソケットと MCP の refresh FIFO は起動時の
  リポジトリのまま (旧も同じ。どちらも `main` が握っている)
