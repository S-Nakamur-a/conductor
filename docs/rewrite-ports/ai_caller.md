API 変更:
- gemini_api を ai_caller::gemini に畳んだ。call_messages_api は private (generate_content)
  になり、外に出るのは GeminiCaller だけ。
- DEFAULT_MODEL 定数と model: Option<&str> を削除。唯一の呼び出し元が常に
  ApiConfig::model (既定 "gemini-2.5-flash") を渡していて、既定値が二重にあった。
- GEMINI_MAX_TOKENS を gemini::MAX_TOKENS へ移動 (Gemini のリクエストのつまみで、
  継ぎ目の一部ではない)。
- AiCaller / TaskEnv / build_caller / GeminiCaller / CommandCaller は旧のまま。

残したコメント (なぜ):
- 外部コマンドのプロトコル (モジュール doc)。ユーザーが設定を書く相手の契約
- 組み込みの claude プロバイダを持たない方針と、provider = "command" が入口である理由
- gemini は素の HTTP なのでリポジトリを読めない
- stdout/stderr を専用スレッドで吸う理由 (パイプのバッファが埋まってデッドロック)
- stdin を必ず閉じる理由 (EOF が無いとブロック) と別スレッドで書く理由
  (レビューのプロンプトは 64KB のパイプバッファを超え、待つとタイムアウトが効かない)
- {prompt} が「どこにも無い」は stdin を意味する
- Gemini 2.5 系は thinking が既定で有効で max_output_tokens を食う (budget 0)
- API キーをヘッダで送る理由 (クエリ文字列はログやトレースに漏れる)
- タスク単位のタイムアウトが要る理由 (数秒の命名と数分のレビューが同じ設定値を共有できない)
