## API で変えた点

- `MarkdownFlavor` → `Flavor` に改称した。
- `render_markdown` / `render_markdown_flavored` の2エントリポイントを `render` 1本に統合した。
  Flavor 引数は省略できなくなった（呼び出し側が明示する）。
- `MarkdownCache` は移植しなかった。新アーキテクチャでは `render` が状態を持てないため、
  キャッシュは呼び出し側の責務になる。付随する `theme_fingerprint` も削除した。
- `apply_background` は移植しなかった。新 crate に呼び出し側がいない。
- `is_markdown_path` は `src/ui/markdown/` ではなく `src/viewer/content.rs` から移した。
  `.mdx` / `.mdown` / 拡張子なしの README にあえて一致させないコメントは踏襲した。
- テストヘルパー `render(text, width)`（旧 Rich 用の省略形）は `render_rich` に改称した。
  公開 API 自体が `render` になったため、`use super::*;` で同名衝突するのを避けるため。
- `is_markdown_path` 用のテストを1本新規追加した（`is_markdown_pathは拡張子だけを大小無視で見る`）。
  この関数がこの crate で新たに公開 API になったため。フィクスチャは旧
  `src/viewer/content.rs` のテストからそのまま持ってきた。

## Viewer に足した事実 (旧に単体テストが無かったもの)

| 新テスト名 | 何を固定するか |
|---|---|
| `mでレンダリング表示に入り行を指す操作で素のソースへ戻る` | `m` で描画が切り替わり、`j` は文書を送り、行を指す操作 (ここではコードジャンプ) が素のソースへ戻して要求された行に着く |
| `切り替えはスクロールを戻し行の選択を畳む` | 切り替えは必ず先頭に着地し、行に紐づいたままの選択を残さない |
| `レンダリング表示は素のmarkdownファイルに限る` | markdown 以外と差分表示では効かない。描画のトグルとキーが同じ述語を読む |
| `実行できる行だけが実行ボタンの桁を開く` (render) | テストの無いファイルでは桁を譲らない |

## 旧との挙動差

- `MarkdownCache` を持ち込まないので、レンダリング済みの行はパネルの `Content` に置き、
  描く直前の `ViewerPanel::prepare` が (テーマ, 折り返し幅, 本文) の指紋で作り直す。
  旧はキャッシュ側が `RefCell` で描画中に埋めていた
- 旧の `render_window` (窓のぶんだけ clone する) は無い。行は `Content` に持ったままで、
  描画が `skip().take()` するだけなので、文書全体を clone する経路が最初から無い
