## ファイルの割り方

| 新ファイル | 責務 |
|---|---|
| `index.rs` | 2 つの索引の持ち場。調査 / 生成 / 読み込みを Task に出し、結果をステータスと起動演出のバーに直す |

## API 変更

1. **`Effect::JumpTo { path, line }` を足した。** `OpenFile` と分けたのは、ジャンプの
   出どころが Viewer の外 (参照一覧、シンボルアクション、ホバーのフッター) にもあるため。
   戻り先を積む場所が 1 つになる。
2. **`Ctx` に `index: &Index` を足した。** パネルの `update` は問い合わせるだけなので共有で足りる。
   `note_open` / `note_change` / `tick_regeneration` は `&mut` が要るので `run.rs` から駆動する。
3. **`Task::SurveyIndex` / `Task::BuildSymbols`、`TaskResult::IndexLoaded` / `SymbolsBuilt`。**
   旧の `BackgroundOp` 2 枠を置き換える。
4. **`CodeMask` を `content::Loaded` に載せた。** 専用の Task を足さず、ファイルを読む
   ワーカーがそのまま作る。tree-sitter を通すのは折りたたみと同じ 1 回で済む。
5. `conductor-core` の `SymbolIndex` に手書きの `Debug`。`Task` が Debug を derive しており、
   載っているシンボル数万件をそのまま出さないため root と件数だけ名乗る。
6. `extract_symbol_at_column` / `masked_symbol_at_column` を持ち込まなかった。画面の桁から
   語を引く口は `word_at_screen` 1 つで、`identifier_occurrences` + `CodeMask` を通る。
   旧は同じ判定が 2 系統 (バイト走査とマスク) あった。
7. **`Workspace::split(root) -> (&mut Panels, &mut Vec<Modal>, Ctx)` を足した。**
   `Ctx` の組み立てが 15 行 × 6 箇所に散り、フィールドを 1 つ足すたびに手で同期していた
   (計画書 1 章 3 が名指しした形と同型)。組み立ては 1 箇所になった。
8. **宣言の行数上限を `hover::MAX_SIGNATURE_LINES` 1 つにした。** 字面から読むときと
   索引の宣言を切るときで、同じ枠に対する同じ上限が別々に置かれていた。

## 挙動差 (旧との違い。全部意図的)

1. **画面全体の 2 文字ヒント (`g` の直後に出ていた Vimium 風のラベル) を落とした。**
   語を選ぶ仕組みが 2 つ (画面全体の 2 文字 / 行内の 1 文字) あり、前者からしか
   シンボルアクションに行けなかった。行内の 1 文字に一本化し、アクションは `ga`。
2. **ホバーの第 2 階層 (参照行のコードプレビュー) を落とした。** 一覧が本文の断片を
   持っているので、同じ情報が 2 段になっていた。参照一覧は `gr` と同じ 1 つに統一。
3. **ジャンプ用の下線 (マウスを乗せた語に付く 2 色の下線) を落とした。**
   フェーズ 5b の課題に無く、ポップアップと同じことを弱く言う表示だったため。
   落とした理由が「同じことを別の表示が言う」なので、戻すなら下線側だけで足りる。
4. **`h`/`l` の向きを直した。** 旧 `references.rs` は見出しの上で `h` が展開・`l` が畳みに
   なっていた (`*collapsed == fold`)。CLAUDE.md の「h/l collapse/expand」に合わせた。
5. **ジャンプ先の画面行を合わせる `source_screen_row` を落とした。** 新しい Viewer は
   独立したカーソルを持たず最上可視行がカーソルなので、飛び先は常に最上行になる。
6. **履歴の端で黙らなくなった。** 旧 `jump_back` は履歴が空だと何もしなかった。
7. **`gd` が定義の上で参照一覧に化ける条件を構文層にも広げた。** 旧は索引が答えたときだけで、
   索引が無いと「今いる行」に飛んで何も起きなかった。
8. **tree-sitter 索引の完成をステータスに出さなくなった。** 旧は FS 変更のたびに
   「Symbol index ready (N symbols)」を出しており、編集のたびにステータスが埋まっていた。
   ログには残す。
9. **ホバーも答えた層を名乗るようにした。** 旧は gd / gi / gr だけが `[index]` /
   `[tree-sitter]` を出し、同じ位置を説明するホバーは黙っていたので、名前一致で拾った
   宣言と索引が位置で解決した宣言が同じ見た目になっていた。定義位置の行の末尾に付ける。

## 実走で確かめたこと

擬似端末で使い捨ての Rust クレートを開き、rust-analyzer を実際に起動して 15 項目。
conductor 本体のリポジトリを開けないのは、動いている conductor が instance lock を
握っているため (`.conductor/conductor.lock`)。

- ファイルを開く → `K` が語を選ばせる → ラベルで選ぶ → 宣言と `src/lib.rs:2` と `2 refs`
- `gd` → ラベル → `Jumped to the definition of 'target' [index] src/lib.rs:2` → `ctrl+o` で元の窓へ
- `gr` → `sum (index) · 1 results` の一覧
- **Repo ▸ Rebuild Code Index** → `Rebuilding the code index for this file…` →
  `index-history.log` に `trigger=manual` の行 → `index.rust.<key>.scip` が置かれる
- 索引が載る前は `[tree-sitter]`、載ったあとは `[index]` を名乗る (ホバーの定義位置の行も)

## 残したコメント (なぜ)

- 参照数を 50 件で切る理由 (`new` は実測 157ms = 10 フレーム落ち)
- 構文層の参照検索がツリー全体を歩く理由 (200 ファイル約 157ms)、描画から呼ばない
- ラベルの桁から出現番号へ戻す理由 (索引は位置で引く)
- タブ展開が識別子の数も並びも変えないので、出現番号を経由すれば列だけ戻せること
- `Enclosing` を `Exact` と混ぜない理由、`via_interface` を直接参照と分ける理由 (実測 9 件中 8 件)
- 一覧を開いた時点で 2 つ目以降のファイルを畳む理由 (実索引で 15 ファイル 63 箇所)
- 波括弧を字面で数えるので文字列リテラルに騙されること
- 調査を 1 本に絞る理由 (列挙 149ms、鍵 1 本 110ms)
