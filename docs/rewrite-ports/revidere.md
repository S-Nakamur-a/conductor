## 残したコメント (なぜ)

実測した外部の癖 (git / AI の応答 / JSON の綴り) と、コードからは読めない設計判断だけを
残した。

- `lib.rs` モジュール doc: 読む側と作る側の入口がどれか
- `analyze.rs` モジュール doc: AI を注入させる理由 (ホスト側の設定が 2 か所に散る)
- `analyze.rs` `Ai::identity`: 固定値だと前のモデルの答えが返り続ける
- `analyze.rs` `analyze`: 毎回ゼロベースで作る / 説明もれが残っても成果物は返す
- `analyze.rs` since_previous の採取位置: AI を待つ数分の間に HEAD が動く
- `analyze.rs` `previous_head`: HEAD が動いていなければ起点も動かさない (空振りに見える
  操作が前の起点を消す)
- `analyze.rs` 差し戻しの `<` 比較: 悪化したら採らない
- `review.rs`: 本当の公開 API は JSON の綴りの方 / `Scope` を 1 枚に混ぜない理由 /
  `artifact_path` を 1 本にする理由 / `Side::Old` を一級で持つ理由 / `reason` を全重要度に
  課す理由 / `Relation` が添字でなく title を指す理由 / `SincePrevious::files` の
  None と空 Vec を畳まない理由。フィールドの `///` は JSON スキーマの説明なので残した
- `order.rs` モジュール doc: ループの主語が項目ではなく変更一覧である理由
- `order.rs` `PAD` / `GAP` / `OrderedLine::owned` / `is_empty` / `build` / `unowned`
- `git.rs` `git()`: core.quotepath の実測 (diff だけがエスケープし、`ls-files -z` はしない)
- `git.rs` `diff()`: 終点が作業ツリーである理由 / `git add -N` を採らない理由 /
  文脈 3 行を保つ理由 / `--find-renames` / `--no-index` の終了コード 1
- `git.rs` `merge_base` / `is_ancestor_of_head` / `changed_files`
- `cache.rs` モジュール doc: 鍵にプロンプト以外 (差分の本文と呼び先) が要る理由、
  ハッシュではなく鍵そのもので突き合わせる理由
- `parse.rs` モジュール doc: 地の文やコードフェンスが実際に付く
- `prompt.rs` モジュール doc: 節・台帳・中核の語を書き換えない理由 (貯めた応答が全滅する)
- `prompt.rs` `user`: base に解決済み ID を渡す理由 / 終点を書かない理由
- `diff/parser.rs`: 空の文脈行の実測 (末尾空白を落とす経路がある) / `\ No newline` /
  `/dev/null` / タブ以降 / ダブルクォート / `" b/"` の分割
- `annotate.rs`: 索引を作る理由 / `LoadError` を 2 つに割る理由 / 索引が先着を採る理由
- `coverage.rs`: 誤分類は機械では見つからない / 同じ項目の中の重なりを衝突に出さない理由
- `forest.rs`: 採取は多重・表示は森 / dangling を捨てない理由 / 巡回を切る / 同じ title は先着
