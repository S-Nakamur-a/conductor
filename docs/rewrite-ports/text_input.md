ファイル構成: 7 ファイル → mod.rs + tests.rs の 2 ファイル (実装 190 行)。
理由: 旧は 1 struct の impl を 27〜90 行ずつ 5 ファイルに割っていて、boundary.rs は
edit/movement の両方から呼ばれる pub(super) を置くためだけに存在していた。1 つの
impl ブロックに 20 メソッドが並ぶ方が「この型が何をできるか」が 1 画面で読める。

API 変更:
- cursor_row_col() → cursor_row()。唯一の利用側 (src/ui/review.rs:134) が col を捨てて
  display_width_before_cursor() を別に呼んでいた。col は同じ計算の重複だった
- select_all_and_clear() を削除。clear() と同体。利用側は handle_key 経由のみ
- move_home / delete_to_line_start が単一行でも行頭 (直前の改行の次) を見るように統一。
  単一行は insert_str が改行を落とすので通常は差が出ない。差が出るのは set_text で
  改行入りの本文を単一行に入れた場合だけで、旧テストはその状態を固定していない
- 単語移動をバイト走査から trim_end_matches / trim_start_matches に置き換え。境界合わせ
  ループが消えた。判定 (ASCII 英数字の並び) は同じ
- Default を derive に (旧は new() 委譲の手書き impl)

残したコメント (なぜ):
- モジュール doc: カーソルは常に文字境界のバイトオフセット / 単一行との差は改行だけ /
  貼り付けは呼び出し側が insert_str に渡す (クリップボードを core が持たない理由)
- move_word_*: 「単語は ASCII 英数字の並び」(日本語は記号扱いになる、という定義)
- handle_key: 消費したら true / 貼り付けは呼び出し側 (App がここで処理を止める理由)

足りない依存: なし。
注記: 旧モジュールは unicode-segmentation を使っていない (char 境界 + unicode-width のみ)。
書記素クラスタ単位の移動/削除は旧に無い挙動なので入れていない。入れるなら別 PR。
