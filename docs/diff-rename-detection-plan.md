# 実装計画書: diff のリネーム検出を有効化する

- 日付: 2026-08-06
- 起点: PR「diff 計算を libgit2 に一本化」で見送った項目。あの PR は Changed files の
  行数が git と食い違う不具合の修正で、リネーム統合は一覧の構成そのものを変える別の
  挙動変更なので切り離した。
- ステータス: draft（着手前）

## 現状

`find_similar` はコードベースのどこからも呼ばれておらず、リネーム検出は最初から
無効。git 本体は既定で有効なので、ファイルを移動すると次のように食い違う。

| | 表示 |
|---|---|
| `git diff` | `src/old.rs => src/new.rs` の 1 エントリ |
| conductor | `src/old.rs` (全行削除) と `src/new.rs` (全行追加) の 2 エントリ |

行数自体はどちらも正しい。違うのは「1 つの移動」と見るか「削除と追加」と見るか。

## ゴール

リネームを 1 エントリに統合し、移動しただけのファイルが「全部消して全部足した」
ように見えないようにする。

## 非ゴール

- コピー検出 (`find_copies`)。リネームより誤検出が多く、レビュー用途での利得が薄い。
- リネーム率のしきい値をユーザ設定に出すこと。まず既定値で困るかを見てから。

## 手順

順序に意味がある。T1 で壊れることが分かれば、そもそも有効化しない判断があり得る。

### T1. レビューコメントの紐づけがリネームで外れないか実測する

一番のリスク。コメントは `file_path` の文字列一致で引いている
(`src/app/review.rs` の `c.file_path == file_path`)。リネームが 1 エントリに統合されると、
旧パスに付いたコメントの受け皿が一覧から消える。

`resolve_changed_path` という救済層はある (`src/app/review.rs` 冒頭) が、これは
`a/` `b/` 接頭辞や表記ゆれの吸収が目的で、リネーム統合を想定した作りかは未確認。

やること: 旧パスにコメントを付けた状態でファイルをリネームし、コメントが
どうなるかを実際に見る。外れるなら、統合後のエントリに旧パスも持たせて
両方で引けるようにする設計が要る。

### T2. 手書きの大文字小文字リネーム除去を撤去する

`find_case_only_rename_indices` は「リネーム検出が無い」前提で、削除+追加のペアを
blob OID とパスの小文字化で突き合わせて潰している。`find_similar` を入れると
libgit2 側が同じ統合をするので、二重に効いて挙動が読めなくなる。

有効化と同時に撤去し、既存の 2 本のテスト
(`test_case_only_rename_filtered_out` / `test_case_rename_with_content_change_kept`)
が libgit2 側の統合で通ることを確認する。通らないなら撤去できないので T3 に進まない。

### T3. `find_similar` を有効化する

`compute_diff_range` で diff を作った直後に `diff.find_similar(Some(&mut opts))` を
呼ぶ。`FileDiff` にリネーム元パスを持たせるかは T1 の結果で決める。

### T4. コストを計測する

`find_similar` は削除/追加デルタ間の類似度計算で、conductor は FS イベントごと
(500ms デバウンス) に diff を再計算する。大きな変更セットで効いてくる可能性がある。

計測は「変更ファイル数が多い worktree で `compute_diff_range` を有効化前後で回して
所要時間を比べる」。体感で分かる差が出るなら、リネーム検出はコミット済み範囲
(`DiffRange::Committed`) だけに絞る案がある。未コミット側は編集のたびに再計算される
一方、作業中にリネームが混ざる頻度は低い。

## 受け入れ条件

- [ ] AC1. ファイルをリネームすると Changed files に 1 エントリで出る
- [ ] AC2. 旧パスに付けたレビューコメントが失われない（T1 の結論次第では
      「失われる場合の挙動を明示的に決めた」に読み替える）
- [ ] AC3. `find_case_only_rename_indices` が消えても、大文字小文字だけのリネームが
      一覧に出ない
- [ ] AC4. 変更ファイルが多い worktree で、diff 再計算の所要時間が有効化前と
      体感で変わらない
