# delineare

実装の前に、読む人が「何を作って何を作らないか」「どの順でやり、各段をどう確かめるか」を 1 枚で掴める計画を作る。
最後に、そのページを Artifact で出す。

$ARGUMENTS

## 手順

スクリプトは `python3 "${CLAUDE_SKILL_DIR}/scripts/delineare.py"` で走らせる (以下 `delineare.py`)。
同じプラグインの revidere のスクリプトから見た目を借りるので、revidere の dir も要る。

1. **作業 dir を作る。** `delineare.py prepare`。1 行目に作業 dir が出る。リポジトリの中なら branch と HEAD が残る。
2. **読む。** 計画の対象になるコードを読む。「確かめたこと」に書くのは、このセッションで実際に読んだ・走らせた・測ったことだけ。
3. **書く。** 下の形の JSON を `<作業dir>/plan.json` に書く。
4. **検査する。** `delineare.py check <作業dir>`。exit 2 なら名指しされた欄を直してもう一度。2 回直しても通らなければ、出た文を利用者に伝えて終える。
5. **ページにする。** `delineare.py render <作業dir>` が `<作業dir>/plan.html` を書いてパスを出す。
6. **出す。** Artifact ツールで plan.html を publish し、リンクを返す。ツールが無いセッションなら、使えないと伝えて plan.html のパスを返す。

## 計画の規則

- **scope** は 1〜2 文。「何をどこまで」。理由や経緯は書かない。
- **premises** は、この計画が成り立つために置いた前提。利用者が決めたこと、外から来た制約。
- **verified** は、コードを読んで確かめた事実。`how` に `読んだ` / `走らせた` / `測った` / `確かめられなかった` のどれかを書く。
  確かめていない予想を書かない。確かめようとしてできなかったことは `確かめられなかった` で書く。
- **make** と **skip** は対にする。skip には `why` (決めた人・理由) を必ず付ける。skip に書くのは「やると思われそうで、やらないもの」だけ。
- **size** は数字で言える規模だけ (変えるファイル数、手順数など)。推測の行数は「~150」のように書く。
- **steps** は、終わるたびに確かめられる単位で切る。`verify` は、その段が終わったと分かる具体的な確かめ方 (走らせるコマンド、見る画面)。
- **figures** は、置き場所や流れが変わる計画なら 1 枚描く。描き方は monstrare の SKILL.md の「SVG の描き方」に従う (class だけで色を付ける、id は `p1-` などで始める)。
- **open** は、まだ決めていないことを 1 件 1 文で。利用者に決めてほしいことはここに書く。
- 日本語で書く。分からないことを埋めない。

### plan.json の形

```json
{
  "title": "1 行の見出し",
  "date": "2026-11-19",
  "status": "draft | doing | done | dropped",
  "scope": "どこまでやるか",
  "premises": ["前提を 1 件 1 文"],
  "verified": [{"text": "確かめたこと", "how": "読んだ"}],
  "make": ["作るもの"],
  "skip": [{"text": "作らないもの", "why": "理由"}],
  "size": [{"label": "変えるファイル", "value": 3, "unit": "ファイル"}],
  "figures": [{"svg": "<svg ...>...</svg>", "caption": "この図が言っていること"}],
  "steps": [{"title": "手順", "body": "何をするか", "files": ["path"], "verify": "確かめ方"}],
  "open": ["決めていないこと"]
}
```

size・figures・open・steps[].body・steps[].files は省略できる。
